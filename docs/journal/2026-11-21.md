## TASK-074: CoreGS 2.0 on Linux, part 1 (libraries, shaders, tests)

- Clean room respected: no PCSX2 source, fork or PCSX2 private material was opened; the changes in `native/hw_gs` only
  replace Windows APIs (loader, surfaces, timer, environment reads, profile clocks) plus one shader workaround.
- `cmake/LinuxCoreGS.cmake` (`-DGT4_LINUX_HW_GS=ON`) builds every CoreGS library, the 36 shaders with the system
  glslangValidator 16.6.0, and the tests. RADV (RX 6600): 257 of 258 pass, 1 skipped (private dumps). lavapipe: 4 fail
  (2 segfaults), cause Unknown.
- Found and worked around a Mesa RADV 26.2.5 bug: `pc.quadrants[strip]` (a push-constant array indexed per
  invocation) reads wrong values on RADV with ACO and with LLVM, while the SPIR-V is valid and lavapipe is exact;
  `hw_tone_hle_exact` had every strip but the first wrong. `hw_tone_strips.comp` now reads it through a `switch` of
  constant indices: exact on RADV and lavapipe.
- The performance HUD and the CPU sampler stay off on Linux (Windows APIs); a Linux file supplies each interface.
