## TASK-074 L1, first part: the Linux host-only build

Branch `task/074-linux-host-build` (from `main` b0008e8a, with the `linux/main` plan commit cherry-picked so the plan and
the TASK-074 entry travel with it).

- The root `CMakeLists.txt` now includes `cmake/LinuxHost.cmake` when `WIN32` is false and returns; on Windows nothing
  changes. The Linux file builds the platform-neutral host libraries and 36 CTest fixtures, with the same target and test
  names as the Windows tree. It needs no private assets.
- Source changes, all behind `#ifndef _WIN32`: `native/host_compat.hpp` (POSIX stand-ins for `_putenv_s`, `tmpfile_s`,
  `fopen_s`, `GetEnvironmentVariableA`), the TSC calibration in `perf_clock.cpp` (`<cpuid.h>`, `CLOCK_MONOTONIC`), the
  thread CPU time in `perf_probe.cpp` (`CLOCK_THREAD_CPUTIME_ID`).
- `standalone_fixture.cpp`: five linked-image checks failed on Linux because the fixture's data is Windows path syntax
  (`D:\ISOs\gt4.iso` is a relative file name on POSIX). They were not weakened. Windows keeps the exact same data, and
  Linux runs the same checks with POSIX paths.
- Results (Confirmed, this machine: openSUSE, Linux 7.3, x86-64): clang 23.1.4 36/36, GCC 16.2.1 36/36 (v2.00), clang
  36/36 (`GT4_TARGET=spec2`).
- Unknown: the Windows CTest and Python run of these changes (no Windows machine in this session). Needed before a merge.
- Open question recorded in `docs/linux/HOST-BUILD.md`: a Windows-made portable folder stores relative image links with
  backslashes, which do not act as separators on Linux.

## TASK-074 L1, second part: the game library and a headless boot on Linux

- Inputs: the local ISO used here is a "1.01" image. Its `CORE.GT4` and `SCUS_973.28` are byte-identical to the pins;
  only `SYSTEM.CNF` (`VER = 1.01`) differs, so the whole-disc hash differs. CORE.GT4 was extracted and verified against
  its pin. The donor `ps2-web-recomp` at `1b48087` matches all 38 source pins only when checked out with
  `core.autocrlf=true`: the pins were taken from a Windows checkout with CRLF endings.
- `ee_producer.py` now has a Linux candidate recipe next to the unchanged Windows one. Results (Confirmed): the ELF
  rebuilt from CORE matches its pin; the Linux translator's output is byte-identical to the frozen Windows inventory
  (328 files, 86,375,038 bytes, `7a1a0909...`); `libps2game.a` has 327 objects (inventory `d5d86cc2...`), the same in
  two independent builds. `tools/ee_producer/build_linux.sh` runs the whole recipe in about 70 s on 12 threads.
- `gt4_headless_smoke` (optional target in `cmake/LinuxHost.cmake`): the donor runtime with the project's source list,
  the CPU rasterizer and the headless host. The game boots and, with scripted presses, goes through the memory card
  dialogs to the name entry and its confirmation; 12,000 frames with no halt and no missing translated entry.
